# Caderno do desenvolvedor — Operação Crachá Geek

## Estrutura esperada — classe
A classe `Participante` representa o molde. Uma solução adequada pode conter atributos privados como nome, email e tipoParticipacao, além de métodos construtores, getters, setters ou um método cadastrar e um método exibirInformacoes.

## Encapsulamento — proteção
O encapsulamento é aplicado quando os atributos ficam privados e o acesso ocorre por métodos definidos pela classe. Isso permite validar dados, controlar alterações e proteger o estado do objeto.

## Objetos — três situações
Os objetos devem ser instâncias diferentes da mesma classe, com dados próprios. Exemplos:
- Ana — ana@email.com — Cosplay
- Bruno — bruno@email.com — Campeonato
- Carla — carla@email.com — Palestra

## Métodos — comportamento
O cadastro pode ocorrer por construtor ou por método específico. O método `exibirInformacoes` deve apresentar os dados do objeto sem acessar diretamente os atributos privados fora da classe.

## Desenho manuscrito — modelo de conferência
O desenho deve conter: Participante; atributos privados; métodos públicos; e, se adotado, tipos dos atributos. Não é necessário que todos os desenhos sejam visualmente iguais, mas a representação deve corresponder ao código entregue.

## README — conteúdo mínimo
Uma explicação satisfatória informa o objetivo do sistema, a classe criada, os atributos, os métodos, o encapsulamento e a criação dos três objetos. Deve ter de 5 a 10 linhas, com linguagem clara.

## GitHub — conferência final
O link precisa abrir o repositório correto e permitir localizar o código, o README e o desenho manuscrito. Um projeto que funciona localmente, mas não está organizado ou acessível no repositório, fica difícil de verificar.

## Critério central
O programa deve demonstrar a relação entre classe, objeto, atributo, método e encapsulamento — e a entrega deve permitir que outra pessoa compreenda e execute o projeto.
